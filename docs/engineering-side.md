# Engineering Side

The Engineering side is repository-aware.

Before Engineering Grill, validate the authoritative Product-to-Engineering handoff package defined in `docs/workflow.md`.

## Goal

Verify feasibility and implementation impact without changing the approved Product behavior.

## Source priority

1. code and executable tests;
2. current repository configuration;
3. current documentation;
4. historical records.

## Important distinction

Not every Engineering question is a Product question.

Use the decision classifier before escalation.

## Context continuity

Every relevant transition must update persistent state or a handoff artifact. The record must be sufficient for a new session to continue without conversation memory.

Apply the complete `ENGINEERING_READY` and `TASKS_READY` contracts from `docs/workflow.md`.
